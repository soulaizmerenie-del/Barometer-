# Barometer — мониторинг рабочих чатов ZFOS

Собирает переписку трёх рабочих чатов Telegram за сутки и помогает свести её
в ежедневный отчёт по [матрице зон ответственности ZFOS MN][matrix].

## Что важно знать сразу

**Ассистент не имеет прямого доступа к Telegram.** Коннектора Telegram в
каталоге Claude нет. Официальный плагин `telegram@claude-plugins-official`
существует, но решает обратную задачу: он даёт инструменты `reply`, `react`
и `edit_message`, чтобы управлять агентом из мессенджера. Истории он не
читает — Bot API её вообще не отдаёт. Поэтому чаты читает не ассистент, а
этот скрипт: под вашей учётной записью, вашими ключами, которые остаются на
вашей машине.

Есть три способа получить сообщения — по убыванию удобства:

| способ | что нужно | история | команда |
|--------|-----------|---------|---------|
| выгрузка Telegram Desktop | ничего, кроме десктопного клиента | вся | `import` |
| учётная запись (Telethon) | api_id/api_hash + вход по коду | вся | `collect` |
| бот | токен от @BotFather, бот в трёх чатах | только новое | `watch` |

**Скрипт работает только на чтение.** Все методы записи Telethon
(`send_message`, `forward_messages`, `edit_message`, `delete_messages`,
`pin_message` и другие) подменяются на исключение при старте клиента —
см. `_lock_read_only` в `barometer/collect.py`. Написать что-либо в рабочие
чаты этот код не может даже при ошибке в вызывающем коде. Чтобы бот получил
право писать, потребуется отдельное явное разрешение и отдельное изменение
кода.

## Отслеживаемые чаты

| ключ | чат | роль |
|------|-----|------|
| `tasks` | Задачи ZFOS | постановка задач — основной источник пунктов отчёта |
| `clientele` | ZFOS♻️🛎 CLIENTELE | клиенты, КП, заявки, поставки под объекты |
| `main` | ZFOS♻️☀️Основной Чат | статусы, монтажи, логистика, импорт |

Названия сопоставляются без учёта эмодзи, пробелов и регистра
(`barometer/config.py`). Если чат переименуют — правится только этот файл.

## Установка

Способам 1 и 3 зависимости не нужны — только Python 3.11+ из стандартной
поставки. Telethon нужен исключительно для способа 2:

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt          # только для `collect`
cp .env.example .env
```

Ключи для способа 2 берутся на my.telegram.org → *API development tools*.
Первый запуск `collect` попросит номер телефона и код подтверждения и создаст
файл сессии `barometer.session` — он в `.gitignore` и в репозиторий не
попадает, как и `.env`.

## Способ 1 (самый быстрый): выгрузка Telegram Desktop

Ключи и вход не нужны. В десктопном Telegram: три точки в шапке чата →
**Экспорт истории чата** → формат **JSON** (медиа можно не выгружать).

```bash
python3 -m barometer import ~/Downloads/ChatExport/result.json --date 2026-08-26
python3 -m barometer digest --date 2026-08-26 --print
```

Импортируются только три отслеживаемых чата, остальные пропускаются.
Без `--date` разбирается вся выгрузка и раскладывается по суткам.

## Способ 3: живой сбор ботом

Бота и токен создаёт только человек в диалоге с @BotFather — ни ассистент,
ни этот скрипт сделать этого не могут. Порядок такой:

1. Открыть **@BotFather** → `/newbot` → задать имя (например `ZFOS Барометр`)
   и логин, оканчивающийся на `bot` (например `zfos_barometer_bot`).
   В ответ придёт строка вида `8123456789:AAH...` — это токен.
2. `/setprivacy` → выбрать бота → **Disable**.
   Без этого шага бот видит только команды и ответы на свои сообщения,
   то есть рабочую переписку не увидит вовсе.
3. Добавить бота во все три чата: «Задачи ZFOS», «CLIENTELE», «Основной Чат».
   Если бот был добавлен до шага 2 — удалить и добавить заново.
4. Положить токен в `.env` (`TELEGRAM_BOT_TOKEN=...`) и проверить настройку:

```bash
python3 -m barometer bot-check
```

Команда скажет по пунктам, что уже готово, а что нет: доступен ли бот,
отключён ли privacy mode, из каких чатов приходят сообщения. Когда всё
зелёное — запускать сбор:

```bash
python3 -m barometer watch
```

**Ограничение способа.** Бот не видит ничего, что было до его добавления в
чат, а пропущенное за время простоя Telegram хранит около суток. То есть
отчёт за прошлые дни так не собрать — для истории нужен способ 1 или 2.
Наблюдатель должен работать непрерывно, поэтому его место — на постоянно
включённой машине или сервере, а не в разовой сессии.

Токен даёт полный доступ к боту, включая право писать от его имени. Если он
где-то засветился — `/revoke` у @BotFather выдаёт новый и мгновенно гасит
старый.

## Способ 2: под своей учётной записью

```bash
# 1. Прочитать чаты за вчера
python3 -m barometer collect --date yesterday

# 2. Свести переписку в дайджест (markdown)
python3 -m barometer digest --date yesterday --print

# 3. По дайджесту заполнить data/tasks/ГГГГ-ММ-ДД.json
#    (статусы, ответственные, участники, исполнители)

# 4. Получить готовый текст отчёта
python3 -m barometer report --date yesterday

# и, если нужно показать, на чём основан каждый статус:
python3 -m barometer report --date yesterday --evidence
```

Шаг 3 — единственный, где нужно решение человека или ассистента: дайджест
показывает переписку, маркеры статусов (`готово`, `в процессе`,
`не могу`, `завтра` и т. п.) и подсказки матрицы, но не решает за вас, что
считать выполненным.

Дайджест из шага 2 можно просто прислать ассистенту в чат — он вернёт
заполненный JSON и готовый текст отчёта.

## Матрица ответственности

```bash
python3 -m barometer matrix --update                 # перекачать из Google Sheets
python3 -m barometer matrix                          # показать подразделения и функции
python3 -m barometer matrix --suggest "Доставка оборудования Нехаду"
```

Последняя команда подбирает функцию матрицы под формулировку задачи и
показывает, кто по матрице — ответственный, участник и информируемый:

```
67%  Техническое подразделение / доставка оборудования клиентам
      Ответственный: В. Баскаков
      Участники: В. Дранчук
      Информируемые: В. Баскаков
```

Снимок матрицы лежит в `data/matrix.csv` — 10 подразделений, 91 функция.

## Формат файла задач

`data/tasks/ГГГГ-ММ-ДД.json`, пример — `data/tasks/2026-08-25.json`:

```json
{
  "title": "Подготовка кп (Уве, МВт, Подгорица)",
  "report_title": "Подготовка кп",
  "status": "in_progress",
  "status_note": "готовность к 26.08",
  "responsible": ["Максим Новоселов"],
  "participants": ["В. Баскаков"],
  "executors": ["Беатрисс", "Максим Новоселов"],
  "division": "Коммерческое подразделение (отделение продаж)",
  "function": "подготовка коммерческих предложений",
  "evidence": []
}
```

`title` — формулировка из задачника, `report_title` — сокращённая для отчёта
(в отчёте пункт часто короче, чем в постановке). Статусы: `done` (готово ✅),
`completed` (выполнено ✅), `in_progress`, `not_started`, `blocked`,
`overdue`, `cancelled`. В `evidence` кладутся сообщения-основания:
`{"chat": "...", "message_id": 123, "author": "...", "at": "...", "text": "..."}`.

## Имена

В матрице, чатах и отчётах люди названы по-разному: `КИ`, `ИК` и
`Игорь Кожемяка` — один человек, `М.Новоселов` и `Максим Новоселов` — другой.
`barometer/people.py` сводит все написания к каноническому виду.

Отдельный случай: **Виталий — это и Баскаков, и Дранчук.** Имя без фамилии
намеренно не разрешается автоматически, чтобы задача не ушла не тому человеку.
